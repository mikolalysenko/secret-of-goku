# SNES port: title module

Spoilers. Title screen, name entry, opening text/inventory patches and Goku's
arrival at the Mana Sword, ported from `engine/title-layer.js`,
`engine/native-names.js` (+ the name prefill in `engine/lab.js`),
`engine/dialogue-patches.js`, `engine/rom-patches.js`, `engine/arrival.js`,
`engine/arrival-event-data.js`, `engine/saiyan-pod.js`,
`engine/native-crater.js` and `engine/native-effects.js`.

| Piece | Where |
| --- | --- |
| Code | `snes/src/modules/title/` (`!CODE_MISC`, `$AB:8000`; about 4 KiB) |
| Data | `!DATA_MISC` (`$EB:0000-7FFF`; about 19 KiB); generated by `snes/gen/title.mjs` (+ `title-arrival.mjs`, `title-lz.mjs`) into `dist/snes/gen/title/` (`title.asm`, `arrival-data.asm`, `arrival-code.asm`) |
| WRAM | `!RAM_MISC` (`$7E:DD80`, `$80` bytes) |
| SRAM | `!PERSIST_MISC` (`$31:6300`, byte 0) and the shared `!persist_goku_active` (`$31:6001`) |
| Tests | `snes/test/title/` (`run.mjs`; browser renderers `ref.mjs`, `arrival-ref.mjs`) |

`snes/gen/title-lz.mjs` is a JavaScript port of the cartridge's LZ
decompressor (C1:4C30, long entry C1:0014) that other generators may import:
`decompress(rom, hirom(0xC77C00))` returns the exact bytes the game writes.

## Title screen

The title and menu program runs from WRAM: reset (`C1:4D0F`) decompresses it
from `C7:7C00` to `7E:8000-D6D2`. On every title entry (power-on, soft
reset, quit) core's title-boot hook calls `modules_title_boot`, where
`title_title_boot` patches three call sites in the WRAM copy after verifying
every original byte (the generator also checks them against the decompressed
program; on any mismatch nothing is patched):

| WRAM site | Original | Hook |
| --- | --- | --- |
| `7E:ADFD` | `JSL $C10014` (logo tiles `DC:E800` → `7E:4000`) | `title_logo_load`: decompress, then copy the GOKU tiles over the Mana word's tiles in the buffer |
| `7E:8869` | text-row writer epilogue (`PLA PLA PLP PLD`) | `title_credit_tail`: if row 17 of the BG2 tilemap buffer (`7F:2B40`) now holds `PROGRAMMED BY NASIR`, rewrite it as the 31-glyph credit |
| `7E:92DD` | `LDA $0070 / STA $420C` in vblank | `title_vblank_hdma`: while row 17 holds the new credit, enable HDMA channel 3 |

- **GOKU lettering**: the browser substitutes BG2 priority-1 pixels in the
  rectangle (143,56,49,48). Every BG2 tile touching that rectangle is unique to
  the logo (tiles `$09-$0F`, `$19-$1F`, `$29-$2F`, `$39-$3F`, `$49-$4F`,
  `$17`; the row-12 blanks stay blank), so the generator renders each of them
  with `engine/title-layer.js` itself (mock PPU, real decompressed tiles):
  native pixels outside the rectangle, the browser's palette-0 indices inside.
  27 tiles actually change. Fades, windows and priorities stay native.
- **Credit**: the browser draws `PROGRAMMED BY NASIR AND CHATGPT` with the
  native font at a 4-pixel inset while row 17 is exactly the original credit
  row. Natively the row is rewritten with the glyphs at columns 0-30 and HDMA
  channel 3 (mode 2, `$210F`) scrolls BG2 by -4 on scanlines 136-143 only
  (table: 127+8 lines at 0, 8 lines at `$3FC`, then 0). Channels 1-3 are free
  on the title (it uses 4-7 for its palette effects). The generator checks the
  composition against the browser layer pixel by pixel. Leaving the title
  during the credit leaves the file select untouched (tested).
- Native WRAM facts used: `7F:2700` BG2 tilemap buffer (DMAed to VRAM `$0800`
  through the program's queue at `7E:91B8`), `7F:0070` HDMA-enable shadow,
  `7E:59F8` attract/credit strings (from `C7:B480`).

## Names

- **Prefill** (`modules_menu_frame`, core's hook at `C0:1E08`, once per menu
  frame in vblank): the first time since the last title entry that `$E4=$E5=0`, `$A156=3`, `$A157=$12`,
  `$A1CC=0`, `$90D0=$2022`, `$9306=$2058`, `$9308=$205C`, write BOY's tiles to
  `$90D2/$9112`, `$A1CC=3`, `$A157=$18` and set bit 1 of `$A20A` (redraw),
  exactly like `prefillName` in `engine/lab.js`. The latch (`!title_flags`
  bit 0) is in module WRAM, which core clears at every title entry (the
  browser re-arms on reload, and its game over reloads the cartridge); later
  edits are never touched. Start commits through the original code.
- **Names in dialogue** (`57 n`, `displayName`) are the story module's view
  at `C0:1866` (`story_name_byte`, see [story.md](story.md)): slot 3 is the
  boy's name kept in the hero slot's tail, Randi when empty or BOY, Primm /
  Popoi for unnamed companions.
- **Crown** (`title_crown_goku`, at the arrival's impact): `$CC00` becomes
  GOKU and the name it held moves to the slot's tail `$CC06` (`crownGoku`;
  safe to repeat: an existing GOKU keeps the tail's name).

## ROM patches

- Starting inventory: `modules_new_game` (core's hook right after the
  new-game inventory initializer `C0:5745`) stores item `$27` (the Drum,
  shown as Goku's Fly item; story patches its name at `CA:A139`) into
  `$7E:CC48`, the store the browser appends to that initializer
  (`engine/rom-patches.js`).
- Player text (`engine/dialogue-patches.js`): `C9:27E4` sword departure
  ("Potos it is, then!"), `C9:306A` Elliott, `C9:339F` Mantis aftermath,
  `C9:3450` sword concern. The sword-pull grunt at `C9:2691` stays
  ":Urrrrrrrgh!" because the browser's arrival read overlay restores it
  (the browser cartridge copy still carries the older ":Easy... Oh!" bytes for
  hash compatibility; the player never sees them). Story compiles its
  relocated events from the same patched text, so both views agree.

## Arrival

### Event

`title_field_frame` (`modules_field_frame`, first in the list) runs the
browser's `beforeFrame` after the game's frame logic:

- **Prologue**: on map 128, with the sword still in the stone (`CF10=0`) and
  the interpreter paused after the boy's grunt (`D0` bit 7, `D1:D3 =
  C9:269F`), the event pointer becomes `title_event_script` (data bank, the
  bytecode of `engine/arrival-event-data.js` relocated by the generator, 339
  bytes). Phase QUEUED.
- **Phases** follow the pointer exactly like the browser's `classify()`:
  offsets `descent` (from `descentWait`, the native 60-frame pause), `impact`,
  `ghost`, `dialogue`; at `finish` the pointer goes to the original tail
  `C9:2790` with `D0=1` and the phase becomes COMPLETE. `!title_ticks`
  counts field frames within a phase (the browser's `ticks`/age).
- **Identity**: at the first impact/ghost/dialogue frame without the arrival
  bit: crown (above), `!persist_goku_active = 1`, `!persist_title_arrival |=
  3` (bit 0 arrived, bit 1 crater/pod scenery). From then on the goku module
  draws Goku.
- **Old saves** (`modules_load`, `title_load`): a GAME FILE past the sword
  pull (`CF10≠0`) without the arrival bit gets `!persist_goku_active` and bit
  0 but no crater, as the browser's `arrival.restore()` decides from
  `nativeProgress()`.
- Story never relocates event 103 (`nativeOnlyEvents`); its fetch hook
  (`C1:E8EF`) sees the arrival bytecode in bank `$EB` like any original
  stream, as the browser's fetch breakpoint sees `C7:4400`.

The native interpreter runs everything else: windows, the five pages, waits,
quake (`2D02/2D03`), the sword-scene flash (`2D06 FF43` / `2D07`), sounds
(`40 02 12 00 88` quake, `40 02 B0 0F 88` hole), the ghost and the original
tail (flash, music, HUD, sword receipt, progression `CF00=1 CF0A=0 CF10=1
CFC1=1`, control at `CA:85A2`). Measured (imported probe state): queued at
frame 41, descent 146, impact 206 (60 frames, as in the browser), ghost 346,
dialogue 382; from the waterfall checkpoint the whole scene to control takes
about 1,600 frames.

### Pictures

Everything is OBJ: 16×16 sprites, priority 3 (above both map layers, below
BG3 windows and the HUD), added after the native sprites (behind them, like
`core_oam_add`, leaving room for staged front sprites), culled at x < -15 and
y < -15 (the OBJ y wrap). Per age, as `drawScene`:

| Phase | Drawn |
| --- | --- |
| Descent | the airborne pod (48×48: 9 cells) from 220 px above, sliding 64 px left, with its 5-orb entry trail in front |
| Impact 0-109 | pod bouncing into the back of the crater (closed, half open from 58, open from 74), radial orbs then sparks, beam heads, centre orb, lightning (ages 0-35), gold sparks (40-109), the crater |
| Impact 77-109 | Goku hops out: cell request (sheet 0, column 37 in the air, 36 landed, row 0) through `!goku_cell_req`; the hero's native body entries (tiles `$1C0-$1EF`, held sword `$144-$149`) are hidden and redrawn as four 16×16 sprites at the hop position with the body's palette |
| After | the crater and the open pod as map-128 scenery whenever the map is faded in (`$E4=$E5=1`), like `craterOnScreen` |

- The crater and the resting pod are map decoration, placed like the
  browser's `placeCrater`: from BG1's scroll as the coming NMI writes it
  (`C0:C170`: `$B0/$B2`, bit 1 flipped by the quake bits `$5E/$5F`) and the
  tile stream's origin `$A8/$AA` (camera = origin + the scroll's offset from
  it modulo 16, in -8..7), so they shake with the ground during the native
  quake and never slip against the tiles. The scene itself (pods in flight,
  effects, Goku) stays on the hero's camera (`$E002-$E020`), as `drawScene`
  does.
- The browser composes the crater and the resting pod per scanline (line y,
  the first visible line being 1), one row above an OBJ at the same y; both
  are placed one row higher than the scene's pod for that reason, and match
  the browser's frames pixel for pixel.
- Hardware limits: at most 32 sprites / 34 slivers per line. The generator
  keeps the stamps that fit beside the crater (6 per line, counted at the
  quake's -2/0/+2 offsets), the pod (3) and the hero's shadow, in priority
  order (centre, lightning, radial, gold sparks, beam heads); the densest
  ages drop up to 19 of 30 browser stamps.
- Art (generated from the browser's own code): pod frames from
  `saiyan-pod.js` (one 15-colour palette), the Potos hole from
  `native-crater.js` at 2× (48×32 → 96×64; 20 sprites from 9 cells after
  mirror deduplication), spell cells from `native-effects.js` (22 cells; two
  palette variants: before age 36 the lightning set, then the dark impact
  sparks; lightning frames 1-2 live in crater palette entries 8-14).
- Emission: fixed lists (crater, pod, trail) have generated unrolled
  emitters (22 cycles per sprite) when wholly on screen; the per-age effect
  lists use a 4× unrolled loop; partly off-screen lists are clipped per
  sprite with X bit 8 for negative x. The high table is cleared per byte.

### Palettes and the flash

The field NMI uploads `7E:0600`, or `7E:BE00` while `$2A≠0`. The sword-scene
flash (`C2:C820`) rebuilds BE00 from 0600 every frame, adding one clamped
amount per channel to palettes 1-15 (OBJ too while `$2A` bit 6 is set). Our
palettes (OBJ 2 effects, 6 crater, 7 pod) are written to 0600 once per visit;
on flash frames the pod and effect colours are put back into BE00 (the
browser draws them unflashed), while the crater keeps the native flash, which
equals the browser's `craterColors` tint (largest offset of BG palettes 1-5
over palette set 26). Without the flash the same offset is derived from three
reference colours in 0600 and applied to 0600 when it changes.

### Speed

Measured over the imported scene (`00:B073`→`00:B077`, core + title + goku):
impact median 33 lines, maximum 43, no frame made late (the game's own frame
logic ends near line 176 every fifth frame); ghost/dialogue about 21 lines;
other maps under one line. During the dialogue the native text engine itself
overruns some frames.

### API for other modules

| Field | Meaning |
| --- | --- |
| `!title_phase` (`$7E:DD86`) | 0 prologue, 1 queued, 2 descent, 3 impact, 4 ghost, 5 dialogue, 6 complete |
| `!title_ticks` (`$DD88`, word) | frames in the phase (the browser's age) |
| `!title_sfx` (`$DD87`) | set to 1 when the descent begins (`playSound('flight')`), 2 at the impact (`playSound('impact')`); the audio consumer clears it |
| `!title_hero_mode` (`$DD8A`) | 0 native, 1 Goku hidden in the pod, 2 hop sprite; `!title_hero_frame/x/y` describe the hop |
| `!persist_title_arrival` (`$31:6300`) | bit 0 Goku arrived, bit 1 crater/pod scenery |

The hop uses `goku_api_cell` once per column and `!goku_cell_req`
(cleared again when the scene ends).

## Tests

`node snes/test/title/run.mjs [title|attract|credit-exit|arrival]` (or
`node snes/test/run-all.mjs title`).

- `title`, `attract`, `credit-exit`: `ref.mjs` renders the browser mod's
  frames in the vendored SnesJs core with `engine/title-layer.js` attached
  and the browser's prefill, and compares Mesen screenshots in 5-bit channels
  within a ±40-frame window (the two emulators boot a few frames apart).
  Title frames 700/760/800/940, the later credits and attract frames
  1040-2200, the BOY name editor and the file select after leaving the
  credit all match exactly. Native attract-mode HDMA band edges differ
  between SnesJs and Mesen around frame 3000 for the original game too, so
  that frame is not compared.
- `arrival` (`arrival.mjs`):
  - *scene*: the browser's probe state before the pull
    (`.local/snes-import/arrival-research__probe__before-pull`) in Mesen,
    against `arrival-ref.mjs` (SnesJs with `engine/arrival.js` and
    `sprite-layer.js`, from `.local/arrival-research/probe/before-pull.json`):
    phase frames within 3, hero slot, persistence, and 16 shots compared in
    5-bit channels with the best browser age within -7..+2 (the native flash
    and water steps run on their own five-frame cadence); the crater and pod
    boxes take their own best age, since the quake's 2 px BG1 shake, which
    moves them with the ground, alternates every other frame. A crater left
    on the hero's camera fails these boxes by 10-24% while the quake runs.
    Side-by-side PNGs: `.local/snes-test/title/arrival/compare/`.
  - *e2e*: power-on with this build to the waterfall
    (`snes/test/checkpoints.mjs --stop=waterfall`), a closed-loop walk to the
    sword (waypoints of a route found in SnesJs), the pull, every page, the
    original tail until control returns; flags, names, inventory, lag,
    scenery, a ring menu round trip.
  - *doors*: from the checkpoint below in a `CORE_TEST` build, door 3 to
    Potos and door 12 back beside the sword.
- **Checkpoint after the arrival**: the e2e run saves
  `after-arrival.mss` (field loop `00:B079`, Goku controllable beside the
  open pod) into the shared checkpoint directory
  (`<main checkout>/.local/snes-checkpoints/`, with `after-arrival.png` and
  `after-arrival.json`). Regenerate with `node snes/test/title/run.mjs
  arrival`.

## Known differences from the browser

- The densest impact ages drop stamps (mostly beam heads) to stay within the
  hardware's per-line sprite limits.
- The scene is layered behind every native sprite; the browser inserts it
  at the hero's OAM index.
- Goku's colours follow the native flash during the hop and the ghost and
  dialogue pages (his palette is the goku module's); the browser draws him
  unflashed. See requests.
- A subtractive native flash on map 128 would darken the crater with the
  map; the browser's tint only adds.

## Requests

- **goku module**: while `$2A≠0` the game rebuilds `7E:BE00` from `7E:0600`
  every frame, Goku's palette included; the browser draws Goku unflashed in
  every flash scene. Restoring Goku's palette into BE00 on flash frames (as
  this module does for the pod) would fix the arrival's hop, ghost and
  dialogue and every other flash scene at once.
- **audio**: `!title_sfx` carries the browser's `flight`/`impact` sounds of
  the arrival.
- **core**:
  - `core_spr_cull` accepts y down to -64; 16×16 sprites with y in
    [-64, -16) wrap onto the bottom of the screen. This module culls at -15
    itself.
  - Unpooled OBJ tiles used on map 128 (see Resources) could join the VRAM
    pool as map-scoped regions.
  - `H.saveStable` hooks the whole address range, so it saves at the next
    instruction anywhere, not at `00:B079`; `arrival.lua` uses its own
    `00:B079`-only save.
  - `H.importSnesJs`: the SPC side of an import does not always resynchronize
    with the CPU. Importing `barrier-audit__potos-probe` a second time in one
    session leaves the game waiting in the APU handshake at `C3:05D2` on most
    frames (46 of 160 frames complete) depending on which instruction the
    import lands on: with this tree's code it happens after the 160-frame
    'off' walk of `snes/test/goku/budget.lua`; without the title module it
    happens after 150, 157, 162 or 163 frames instead. That test then fails
    on "no added lag frames" although no module code runs longer. Applying
    imports at the captured PC (the field loop's NMI wait) would make them
    deterministic.
  - `docs/agents/snes-rom.md` engine anchors: the field NMI's palette DMA
    source is `7E:0600` (`7E:BE00` when `$2A≠0`) and the OAM DMA source is
    `7E:0800` (`$220` bytes).
  - The module would run about 25% faster under `CORE_FASTROM`.
